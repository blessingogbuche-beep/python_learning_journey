“Before you write code, plan the solution, like planning a trip before
 you drive. If you start typing without a plan, you often find halfway
  through that you don’t know what the program needs, what it should 
  do with it, or what it should show at the end. Then you stop, delete 
  code and start again. A plan answers three things first: what goes in
   (input), what the program does with it (process) and what comes out 
   (output). Then writing code is just turning your plan into Python,
    and you make fewer mistakes.”
